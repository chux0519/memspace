# MemSpace 竞品评测与检索优化计划

2026-10-31。先对比 **agentmemory、Nautilus Compass、Hindsight**，用相同输入量化
MemSpace 的来源找齐、跨语言检索、实际注入和资源开销，再根据失败发生的环节优化。
第一轮交付公开英文基准和100道新中英题的对照表，不把各家问答宣传分数当成检索差距。

## 对比项目

| 项目 | 选择理由 | 本轮用途 | 需要控制的差异 |
|---|---|---|---|
| agentmemory | 已精确复现，方法和逐题收据公开 | 固定 BM25 对照，验证新增语义能力值多少 | 已公布的是检索组件，不含向量、捕获与摘要；不代表其全部产品能力 |
| Nautilus Compass | 默认 BGE-M3，有检索脚本，支持句段与会话检索 | 比较相同 embedding 下的粒度、候选组合和排名 | 官方脚本按数据集题型选择路径；其 P@5 实际是任一命中，需要统一评分 |
| Hindsight | 有公开评测、多路检索及多语 embedding/reranker 配置 | 学习事实与原文关联、时间检索、候选配额和重排 | 原生 retain 会提取事实，必须计入建库成本，单独评估原生流程 |

第一轮不接入 Mem0 托管版、Zep Cloud 和 Supermemory。它们可留作后续产品验证，
本轮优先完成可固定源码、在本机定位差异的项目，减少服务版本和回答模型造成的干扰。
MKQA 作为后续 embedding 诊断集，不计为产品竞品。

依据：[agentmemory 公开口径](https://www.agent-memory.dev/benchmarks)、
[Compass 复跑入口](https://github.com/chunxiaoxx/nautilus-compass/blob/main/scripts/reproduce_lmes_retrieval.sh)、
[Compass 计分](https://github.com/chunxiaoxx/nautilus-compass/blob/main/scripts/lmes_metrics.py)、
[Hindsight 多语配置](https://hindsight.vectorize.io/developer/multilingual)与
[检索机制](https://hindsight.vectorize.io/developer/retrieval)。实施前固定第三方 commit、依赖和配置，
这些主干文档链接仅用于解释选择理由。

## 已有基线

| 层次 | 已验证结果 | 在本计划中的作用 |
|---|---|---|
| 英文会话检索 | MemSpace 403/470，85.74%；agentmemory 398/470，84.68% | 保留完整500题和官方变换，作为公开回归基线 |
| 真实 Build 和 hook | 内部100题中，可自动注入的正例57/79，72.2% | 检查搜索改进是否真正进入注入文本 |
| 离线大 reranker | 同一内部回归集67/79，84.8%；CPU12候选 p50/p95 为0.86/4.62秒 | 质量参考，暂不接同步 hook |
| 查询诊断 | 公共英文检索 p95 71.6ms；20题抽样中，摘要生成和逐词命中统计各约13ms平均开销 | 优先验证可保持结果一致的降耗 |

详细结果见 [LONGMEMEVAL.md](LONGMEMEVAL.md)、[RERANK.md](RERANK.md)。
旧题已用于开发；不能当成新方案的独立泛化证据。85.74%也不是跨语言或实际注入成绩。

## 比较口径

### 原始来源检索

MemSpace、agentmemory BM25、Compass 使用相同完整来源、日期和不透明 ID，不运行
回答或判分 LLM。沿用 agentmemory 的 LongMemEval loader 和 scorer；470道可回答题
计质量，30道不可回答题只计执行覆盖。最终返回前5个不同来源会话，另测前20个会话。
Compass 每个片段须先关联到原会话，排名稳定去重，不让一个会话占多个名额。

adapter 只接收来源、问题、允许使用的日期、作用域和预算。答案、标准来源、题型、
开发测试标签均不进入检索器。Compass 的官方题型路由可另复现为原报告核对行，
主比较采用固定的、无需题型标签的路径；所有适配修改保存为补丁。
原始来源、分块、截断及过滤差异要逐项记录，不能默默把原实现替换成自写算法。

MemSpace 和 Compass 的受控语义对照优先共用一个 BGE-M3 embedding endpoint，
固定权重、tokenizer、CLS pooling、归一化、512输入上限、量化和查询前缀。
仅写“同用 BGE-M3”不算同模型配置。若对方无法接共享 endpoint，就另列其原生模型行，
先做向量一致性检查，再决定是否适合归因到检索算法。agentmemory BM25 行不用 embedding。

### 原生记忆检索和证据交付

Hindsight 使用原生 retain/recall，配置多语 embedding 和多语 reranker；另做关闭
reranker 的消融。该流程有事实提取、索引与后台处理，独立成表，不能命名为无生成式
处理的 BM25 组件对照。MemSpace 和 Compass 同样保留各自实际索引与截断路径作为原生行。

只计系统真实返回且能追溯的证据：派生事实要附原文来源，凭真实 citation 映射，
不由 scorer 根据标准答案反查来源。事实条数、会话条数、展开后的原文数分别记录；
不能把“一条事实引用许多会话”算作只消耗一个来源的优势。
事实改写采用预先标注的字段和值及允许别名核对，必要时匿名复核；不能拿模型判分
冒充纯检索分，也不能把字面短语没出现直接判定为语义错误。

统一报告1000个 cl100k_base 参考 token 预算内的可见证据覆盖，包含必要来源元数据；
不改写正文来凑预算，只截取系统按原排名提供的完整证据单位。另报告各系统默认预算。
MemSpace 的真实 hook 仍单列最多6条、6000字符的生产配置，不把外部结果拼装成伪 hook。
首次交付、重复抑制与按需工具补读分开计分。

## 题集与标注

| 题集 | 规模和用途 | 使用规则 |
|---|---|---|
| LongMemEval-S | 原500题，470道质量计分；同一已验证 SHA256 | 对齐公开英文成绩，保留逐题收据；已用作开发回归 |
| 新中英编码题 | 20个独立场景，每场景5种语言条件，共100次查询 | 探索中英互查与产品差异；不宣称100个独立场景 |
| 现有 coding-v2 与会话预算题 | 100题加独立8题专项 | 检查注入、3至4条互补证据、来源和预算回归；不混入新题成绩 |

20个新场景包含6个单事实、4个多来源互补、3个时间或版本变化、3个长正文场景和
4个负例。负例覆盖库内无答案、近义不同实体、答案仅在另一个项目、过期版本不适用。
每个场景包含来源正文、事件时间、项目、会话、标准证据组、正文证据位置，以及
完整的相关来源集合。支持性证据与必须证据分别标注，用于同时计算 precision 和找齐。

五种语言条件是：

| 条件 | 问题语言 | 来源语言 |
|---|---|---|
| 英文对照 | 英文 | 英文 |
| 中文查英文 | 中文 | 英文 |
| 中文对照 | 中文 | 中文 |
| 英文查中文 | 英文 | 中文 |
| 混合语言 | 中英混排 | 每条来源按固定分配使用一种语言 |

每种条件使用独立 corpus/namespace；一个事实的中英文翻译不会同时出现在检索库里。
翻译保持实体、数字、时间、否定和标准答案不变，允许自然改写。比较中文查英文与
英文对照、英文查中文与中文对照的配对差值，避免把语料难度误判成语言损失。
项目隔离另查原生查询路径，不能由 adapter 预先删除越界文档后宣称产品隔离通过；
未提供该能力的组件标为不适用，并保留在纯检索对照中。

按场景及共享来源分组：8个场景开发、12个场景留出，同一事实的所有翻译、近邻、
多来源题和版本链必须同组，正负场景分层，固定种子20261031；对应40次开发和60次留出查询。
先冻题集和标注 SHA，再运行系统；开发阶段只看开发分项。
留出仅在配置固定后统一核验。若已经查看并据此调整，标记为回归集，再加新场景。
事后标注和 agent 自拟题明确标识，不能冒充独立人工盲测。首轮规模用于定位问题，
判断稳定领先时再扩充独立场景，不靠复制翻译扩大置信度。

## 指标与失败定位

| 指标 | 定义和用途 |
|---|---|
| Strict all-source@5 | 前5个不同会话包含全部标准来源；公开检索主指标 |
| Any-hit@5 与 fractional recall@5 | 分别记录至少找到一个、找到多少；不把任一命中叫找齐 |
| All-source@20 与候选覆盖 | 前20来源和实际候选池各自是否含全部必要来源，定位召回上限 |
| 可见证据找齐 | 最终交付文本中是否包含所有必需事实，检查正文截断和打包损失 |
| 相关性 precision | 返回的不同来源中相关来源占比，仅用于完整标注的新题；空返回为 null |
| 负例误注入与项目越界 | 误注入、错误版本、越界单列，不用正例平均数掩盖 |
| 语言损失 | 两个方向各自相对同语种对照的配对百分点差，不只报混合平均 |
| 延迟与体积 | 检索及原生交付各报 p50/p95、超时率、实际返回参考 token |
| 资源与建库 | 建库时间/输入输出 token/请求数、索引大小、空闲和查询时内存峰值 |

每个失败先定位最早断点：原始来源在进入索引前已丢失、未进入实际候选、候选有但
前5没有、已进入前5但交付文本丢失、交付了错误实体或版本。证据集未标全的疑似误报
单独复核，修正标注后所有系统一并重跑，不能只对某家改分。

质量按题型、语言方向、多来源数量和正文长度拆分。报告实际失败和完成分母，
错误不静默剔除；新题按场景做配对 bootstrap，公开题按问题做配对分析。
重复运行只用于稳定性和性能，不扩大独立样本数。

## 性能测量

分开测建库后首次查询、重复查询和服务启动；固定机器、CPU线程数、硬件模式和并发。
运行顺序轮换，禁止一个系统计查询向量耗时而另一个复用未计时向量。离线缓存向量
只能用于质量消融，必须另跑包含真实模型调用的延迟测量。

用同一批公开来源测试小库和合并后的全局库；独立构造1千及1万会话规模，记录实际
来源数和干扰集 SHA。未标注的真实干扰不能直接视作无关。全局库实验与每题 haystack
分表，不能拿后者成绩代表生产规模。先跑并发1，再测并发4及后台建库争用。

内存计系统完整进程树及本地 embedding/reranker、数据库服务，公共服务只计一次。
区分常驻、请求峰值、文件缓存和索引磁盘；可用隔离 cgroup 同时记录 anon/file。
远程模型资源标为未测，不与全本地总资源作优势比较。不能预设 SQLite 比内存索引省 RAM。

## 优化顺序与验收

以下数字是候选方案的开发门槛，不是预报成绩。每次只改变一类机制，保留基线、
消融和代价，不预先承诺所有方法叠加有效。

| 顺序 | 要验证的改动 | 选择依据和验收 |
|---|---|---|
| 1 降低无效计算 | 先确定最终排名再生成摘要；合并逐词命中统计 | 必须保留排名、分数、匹配元数据和证据文本；公开500题逐项一致，同机 p95 目标从71.6ms降至40ms以内 |
| 2 保留和召回来源 | 修复长正文进入索引前的丢失；比较会话/轮次窗口；给词法与语义各自候选配额 | 候选缺证据时才做；检查真实截断，来源边界、否定和项目过滤不丢；不能只增加最终条数 |
| 3 改善排序与接纳 | 对同一候选比较原规则、轻量特征排序、小型多语 reranker | 候选已含答案时做；所有分数/权重只在开发场景选，不向模型提供标签 |
| 4 补全交付证据 | 按新增相关证据和长度选择，关联必要上下文，减少重复 | 前5已有来源却未注入时做；维持预算，对照是否同时带入更多无关记录 |
| 5 处理实体与时间 | 区分名称相似的实体、事件时间与记录时间、历史与当前版本 | 仅在该类错误占比明显时做；历史问题保留旧记录，不使用统一“越新越好”加分 |

质量候选先要求新题开发正例可见找齐提升至少5个百分点、相关性 precision 不下降、
负例误注入不增加、范围越界和来源错误为0，再进入留出评估。留出报告配对收益、
损失和置信区间；小样本门槛通过不等于已证明稳定领先。

公开英文里程碑先定 **至少414/470，88.1%**，长期挑战423/470，90%；两者都必须
伴随完整分项和新题验证。如果跨语言提升但英文退步，明确保留为可选配置，不能
用另一个指标隐藏回归。

同步注入的性能门槛是含真实 embedding/重排的完整 hook p95 不超过1秒、超时率
低于1%，留出距1.5秒 deadline 的余量；性能探针重复至少1000次，质量样本数仍按
独立题计。与当前同题基线相比，中位注入 token 增幅超过10%的方案须独立报告预算
匹配结果，先作为另一工作点，不直接替换默认策略。

大 BGE reranker 维持离线参考。先测一种较小多语模型；仅在其质量合格后比较量化
或选择性调用。是否调用依据可校准的候选信号，不能拿一个未校准的 BM25 分数差
充当跨问题置信度。现有两路等权 RRF 曾退步，后续若重试必须逐路消融、检查索引统计，
不能将“多加一路”本身当成收益。

## 执行阶段与交付

| 阶段 | 工作 | 完成条件 |
|---|---|---|
| 第一阶段 | 固定源码/模型/依赖，审计 Compass 路由和来源映射；用10题冒烟 | 标签未进入系统，原文没有意外截断，各系统错误可观测；形成可运行配置清单 |
| 第二阶段 | 扩展原 runner，完成三个无生成式处理的检索对照：MemSpace、agentmemory、Compass | 完整500题、同一官方评分、逐题排名和 provenance；受控语义配置单列 |
| 第三阶段 | 冻结并运行100道新中英题；接 Hindsight 原生记忆对照 | 两个跨语言方向、负例、候选/排名/可见证据断点及资源成本可追溯 |
| 第四阶段 | 按最主要断点做一次优化；先开发集选择，再固定配置跑留出与旧题 | 给出提升、退步、时间与 token 代价，保存失败实验；决定默认或可选配置 |
| 第五阶段 | 必要时增加独立场景；再做 MKQA 或小规模编码交接任务 | 验证泛化或任务成功率，不以翻译复制数代替独立证据 |

第一阶段就用真实10题测单题建库、查询和资源成本，估算全量耗时。计算量大的公共
语义编码按相同来源文本和模型 fingerprint 缓存，不能跨题复用搜索索引或输出排名。
Hindsight 先用自包含的新题小库，达到效果且完整记录提取成本后再考虑500题全量。
执行中不自动调用付费外部模型，不上传真实历史；若本地依赖或硬件不满足，先交付
已完成的组件表及明确缺项，不伪装为原生流程全量比较。

沿用 `scripts/bench/longmemeval/` 和 `scripts/bench/retrieval/`，新增 adapter、来源映射
及分阶段 trace；不重写官方 loader/scorer。运行前冻结配置及源码，输出每题来源排名、
文本哈希、可见证据、时延、异常、模型调用数和完整 manifest。原文与私有收据留在
gitignore 的 runs 目录；提交合成题、审查后的聚合报告、脚本及收据 SHA。

最终对照表分别展示原始来源检索、原生证据交付、MemSpace hook、性能资源四部分。
对“超越”的判断要求在相同输入和预算下找齐率提高、无关结果受控，并给出延迟与资源
代价；单独超过一个公开英文点估计，只能称该项更高。
